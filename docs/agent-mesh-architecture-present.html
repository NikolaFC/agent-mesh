Agent Mesh v0.3.0 · Architecture Brief

让 Agent 不再是孤岛。

Agent Mesh 是一个轻量、文件优先、跨终端可同步（experimental）的多 Agent 协作层：用 .mesh/ 作为共享状态，让 OpenClaw、Hermes、Claude Code、Cursor、Codex 看见彼此在做什么。

file-as-API zero server core pulse · task · shared knowledge cross-device sync · experimental
README / PROTOCOL source2026-05-12
开场一句：以前人是消息总线，现在 .mesh/ 变成消息总线；Agent Mesh 的核心不是“又一个工具”，而是让多个 AI runtime 共享工作真相。
Problem
Before Agent Mesh

人类成了上下文搬运工。

  • 每个 Agent 有独立 context window。
  • Hermes 完工要写大交接文档，OpenClaw 再人工拼状态。
  • “进展怎样？”需要重复查日志、PR、handoff。
  • 状态过时、互相踩任务、阻塞不可见。
After Agent Mesh

一条命令看全局。

  • mesh status 汇总 agent freshness、任务、阻塞。
  • Pulse 显示谁正在做什么。
  • Task 记录 owner、进度、verdict、证据历史。
  • Shared knowledge 保存跨 agent 都该知道的当前真相。
Problem: agents cannot see each other02
强调真实起源：OpenClaw 管编排/记忆，Hermes 管 PR 实现，两个系统并行但没有共同状态层。
Core Thesis

不需要先建中心服务器。
Repo 本身就是 API。

任何能读写文件的 Agent，都能接入 Mesh。核心协议保持本地、透明、可 diff、可审计。

Design principles
  • File-as-API：固定路径 + 简单 schema。
  • Zero dependency core：Python 标准库即可。
  • Git-native：历史、diff、merge；跨设备 sync 目前 experimental。
  • Append-friendly：保留 history，不靠覆盖口述交接。
  • Explicit sync：远端同步由命令触发，不做隐式后台写网。
Architecture stance03
这页讲哲学：越底层越简单。文件层先跑通，MCP/远端/迁移都是可选扩展，不污染 core。
High-level Architecture
.mesh/shared state layer
OpenClaw主编排器；记忆、频道、heartbeat；读全局，写 openclaw pulse。
Hermes独立 coding/runtime；处理 PR、实现、修复；写 hermes pulse + task history。
Claude / Codex审查、重构、one-shot coding；按稳定 agent name 接入。
Cursor / Editor编辑器内 Agent；读任务上下文，避免重复劳动。
State Machines长任务通过 bridge 写入 task + sm-* pulse。
Peer runtimes · shared state04
重点：Mesh 不拥有 Agent，也不替代 OpenClaw/Hermes。它只是共享黑板；每个 Agent 写自己的 pulse，task owner 管任务字段。
Core Data Model

三层稳定协议：Pulse / Tasks / Shared

Pulse

实时心跳。每个 Agent 一个小 JSON，显示状态、当前任务、最近动作、阻塞与 next actions。

.mesh/pulse/{agent}.json
Tasks

工作项真相。记录 owner、status、verdict、priority、progress、links 和 append-only history。

.mesh/tasks/active/*.json
Shared Knowledge

项目级 operational memory：薄上下文、当前决策、阻塞、runtime status、SOP 链接。

.mesh/shared/
Optional MCP

实验层：注册 session、申请授权、生成 bounded context pack；不改变 core 文件协议。

.mesh/mcp/
File-capable agents can join05
别把 Mesh 讲成数据库。它是“约定好的文件结构 + CLI 安全写入 + schemas”。

CLI Surface

演示时最容易讲清楚的 8 条命令。

Reliability & Safety
Write safety

锁 + 原子替换

POSIX 平台写操作使用 .mesh/.lock，JSON/Markdown 通过同目录临时文件再 atomic replace，降低多终端写坏状态风险。

Schema hygiene

validate / doctor

mesh validate 检查结构；doctor --fix-safe 做机械安全修复：索引、legacy 字段、别名归一、terminal task 归档。

Access boundary

MCP 有授权闸门

跨 Agent 读取 transcript 必须 request → grant；支持 allow-once / scoped allow-session / deny，并写 audit log。

File core · gated MCP09
这页回答“可靠么/安全吗”。核心状态透明可审计，跨会话上下文读取不默认放开。
System Boundary

Agent Mesh core 做什么？

  • 提供 mesh CLI。
  • 维护 .mesh/pulse、.mesh/tasks、.mesh/shared。
  • 定义 schema、索引、validate、doctor。
  • 提供实验性 cross-device state sync。

它不做什么？

  • 不替代 OpenClaw / Hermes / Claude Code。
  • 不自动读取或注入所有 raw transcript。
  • 不强迫 agent 更新 pulse；接入由 host prompt / heartbeat / watchdog 保证。
  • 不把 secrets、credentials、runtime logs 当迁移默认项。
Boundaries prevent architecture creep10
用这页防误解：Agent Mesh 不是“全能中心脑”，它是共享状态协议。
Experimental MCP Layer

可控地读取
另一个 Agent 的上下文。

Mesh MCP 是实验扩展：当 task/pulse/status docs 不够时，Agent 可以申请读取 OpenClaw ↔ Hermes 的 session transcript，并生成有 token budget 的 context pack。

requestgrantauditcontext packstdio MCP
mesh mcp session register \ --agent hermes \ --session-id bug-123 \ --transcript /path/to/log.txt mesh mcp access request \ --requesting-agent openclaw \ --target-session hermes:bug-123 \ --reason "handoff" mesh mcp access decide --id <request> --decision allow-once --by satoshi mesh mcp context pack --requesting-agent openclaw --target-session hermes:bug-123 --token-budget 4000
Transcript scope: OpenClaw ↔ Hermes11
MCP 层的核心价值不是工具列表，而是“带权限的跨 Agent 上下文织物”。
Takeaway

一句话总结：

Agent Mesh 把多 Agent 协作从聊天转述，变成可读、可写、可验证的共享状态协议。

Today

本地 Mesh + 实验性跨设备

OpenClaw、Hermes、Claude Code、Cursor 共享 task/pulse/context。

Next

更稳的 Agent 接入

把 prompt、heartbeat、watchdog、state machine bridge 做成标准 onboarding。

Future

受控上下文网络

MCP context pack、remote QMD、persona migration，逐步从“状态共享”走向“协作底座”。
